# Розгортання на міні-ПК

Покрокова інструкція для адміністратора клубу. Розрахована на одного
адміністратора в зміну, без ІТ-підтримки — виконується один раз при
відкритті, далі система працює сама.

---

## 0. Перед початком

У `src/config.js` позначені рядки `⚠️ уточнити` — `OPEN_TIME`, `CLOSE_TIME`.
Це час відкриття/закриття залу: він визначає автозакриття візитів і межу
доби у звітах. Якщо власник ще не підтвердив ці цифри — уточнити
**до** відкриття, зміна значення пізніше не перерахує вже закриті візити
заднім числом.

---

## 1. Google Drive for Desktop

1. Встановити [Google Drive for Desktop](https://www.google.com/drive/download/) під **окремим Google-акаунтом клубу** (не особистим акаунтом адміністратора — акаунт лишається з клубом, якщо адміністратор зміниться).
2. Увійти, дочекатися синхронізації. У провіднику Windows зʼявиться диск **G:** (буква може відрізнятись — залежить від налаштувань).
3. Перевірити: у налаштуваннях Google Drive for Desktop увімкнено «Streaming files» чи «Mirror files» — для бекапів підходить обидва режими, головне щоб папка була видима і доступна для запису без затримки.

## 2. Структура папок

На диску G: створити:

```
G:\Мій диск\Геркулес\База\Бекапи\
```

Саме цю папку `Бекапи` система попросить вказати при першому запуску.

**Важливо (розділ 8 ТЗ):** ця папка не шериться з жодним акаунтом і не
лежить у спільному диску (Shared Drive) — у бекапах медичні нотатки
клієнтів.

## 3. Встановлення застосунку (локально, без GitHub Pages)

Застосунок працює **локально** з диска мінн-ПК — код береться з git-копії
репозиторію, а не з інтернет-адреси. Це прибирає залежність від того, чи
підняті GitHub Pages, і від інтернету взагалі для щоденного відкриття
(інтернет потрібен лише для оновлень, розділ «Оновлення» нижче).

**Якщо на цьому Chrome цей застосунок (будь-яка стара версія) уже
відкривався раніше** — перед першим запуском нової версії відкрити
`chrome://settings/content/all` → знайти адресу застосунку → «Очистити
дані». Service Worker з попередньої версії лишається активним на origin
і продовжує віддавати старий закешований код, поки його не скинути
вручну — Chrome не робить це сам при заміні файлів на диску.

1. Встановити [Git for Windows](https://git-scm.com/download/win) та
   [Node.js LTS](https://nodejs.org/) (за замовчуванням, обидва потрібні лише
   один раз при встановленні).
2. Клонувати репозиторій, наприклад у `C:\Herkules\herkules-desk`:
   ```
   git clone https://github.com/Artem-Ushenko/herkules-desk.git C:\Herkules\herkules-desk
   ```
3. У цій папці виконати один раз:
   ```
   npm install
   ```
   Це ставить React, Vite та решту залежностей у `node_modules\` —
   після цього кроку інтернет для запуску вже не потрібен.
4. Перевірити `src/config.js` — розділ 0 вище.
5. Подвійним кліком запустити `start-desk.bat` із кореня репозиторію.
   Скрипт сам збирає застосунок (`vite build` → `dist/`), піднімає
   локальний сервер на `http://localhost:8080/` (`vite preview`, той
   самий продакшн-білд, без dev-режиму) і відкриває його в окремому
   вікні Chrome (`--app=`) — без адресного рядка, як окремий застосунок.
   Формальне «Встановити застосунок» через меню Chrome не потрібне.

## 4. Автозавантаження

1. Переконатися, що в `start-desk.bat` заповнені шляхи `CHROME` і
   `PROFILES` (розділ «ЗАПОВНИТИ ПЕРЕД ЗАПУСКОМ» на початку файлу) і, за
   потреби, адреса каси `POS_URL`.
2. Створити ярлик на `start-desk.bat` і покласти його в `shell:startup`
   (ввести цей шлях в адресний рядок провідника — відкриється папка
   автозавантаження Windows). Або зареєструвати через Планувальник
   завдань, тригер «При вході в систему» — так надійніше, бо є контроль
   над затримкою старту й правами запуску.
3. Якщо в залі два монітори — після першого запуску перетягнути вікно
   CRM на потрібний монітор і розгорнути на весь екран: Windows зазвичай
   запамʼятовує позицію вікна для наступних запусків.

## 4а. Якщо на цьому ПК є ще й «Геркулес Шоп»

Кожен проєкт запускається вручну сам по собі своїм власним
`start-desk.bat` (у своїй папці) — так і лишається типовий щоденний
запуск однієї системи. Коли ж на тому самому ПК/стійці треба підняти
одразу й `mini_shop_POS` (той самий стек, той самий принцип запуску),
є окремий спільний скрипт **на рівень вище**, у батьківській папці, що
містить обидва проєкти (наприклад `D:\sport_shop\`, а не всередині
`gym-POS`): `start-desk-both.bat`. Він очікує `gym-POS` і
`mini_shop_POS` як сусідні папки, збирає й піднімає обидва застосунки
(Клуб — порт 8080, Шоп — порт 8081) і відкриває два вікна Chrome, кожне
у своєму профілі. Автозавантаження (крок 4 вище) тоді ставиться на
цей спільний `start-desk-both.bat` замість `start-desk.bat` тут.
Оновлення обох одразу — `update-both.bat`, там само, на рівень вище.

## 5. Перший запуск

1. Відкрити застосунок (або перезавантажити ПК — має піднятись сам через автозавантаження).
2. Перейти в **Налаштування → Бекап → «Обрати папку бекапів»**.
3. У діалозі вибору папки вказати `G:\Мій диск\Геркулес\База\Бекапи`.
4. Система одразу зробить перший бекап. Перевірити:
   - у шапці застосунку індикатор показує свіжий час: «Копія: HH:MM ✓»;
   - у папці `Бекапи` зʼявився файл виду `herkules-2026-08-09-1430.json`.
5. Зачекати 2–3 хвилини на синхронізацію Google Drive, відкрити [drive.google.com](https://drive.google.com) в браузері на іншому пристрої (або з телефону) — файл має бути видно там само.

## 6. Тест відновлення — обовʼязково до відкриття клубу

Мета: переконатись, що бекап справді можна підняти на **іншому** компʼютері,
а не лише припустити це.

1. На іншому компʼютері (або в іншому профілі Chrome — «Гість» на цьому ж) клонувати той самий репозиторій, `npm install`, і підняти тимчасовий сервер — `npm run dev` (детальніше — в `README.md`) — і відкрити адресу, яку виведе Vite (типово `http://localhost:5173`).
2. Створити тестового клієнта, щоб база не була порожня.
3. Налаштування → «Вибрати файл» → обрати щойно скачаний з Google Drive файл бекапу з основного ПК.
4. Перевірити прев'ю: кількість клієнтів/візитів/оплат і дата знімка мають збігатись з тим, що на основному ПК.
5. Підтвердити відновлення (кнопка натискається двічі — захист від випадкового кліку).
6. Переконатись, що клієнти й абонементи з основного ПК зʼявились тут.

Якщо цей крок не пройдено — бекап існує лише в теорії. Не відкривати клуб
без пройденого тесту відновлення.

## 7. Оновлення застосунку

Код оновлюється вручну, за потреби (наприклад, коли розробник повідомив про
виправлення) — не автоматично при кожному запуску, щоб не підхопити
незавершену зміну посеред робочого дня.

1. Закрити вікна CRM (`start-desk.bat`), якщо вони відкриті.
2. Запустити `update.bat` у папці застосунку — він зробить `git pull`,
   за потреби оновить залежності (`npm install`) і одразу пересобере
   застосунок (`npm run build`), щоб помилку збірки було видно одразу,
   а не при наступному запуску стійки.
3. Запустити `start-desk.bat` знову (або перезавантажити ПК).

Потребує інтернету лише на час самого оновлення — після завершення
`update.bat` застосунок знову працює повністю офлайн.

## 8. Щотижнева перевірка

Раз на тиждень, з телефону, без заходу в зал:

1. Відкрити застосунок Google Drive на телефоні (той самий акаунт клубу).
2. Перейти в `Геркулес → База → Бекапи`.
3. Перевірити дату найновішого файлу — має бути не старше кількох годин.

Якщо файлів давно не оновлювалось — на робочому ПК в шапці застосунку буде
червоний індикатор «Копія: N днів тому ⚠». Причина зазвичай одна з:
- Google Drive for Desktop вивантажився після оновлення Windows;
- диск G: зайняла інша програма/пристрій;
- застосунок довго не відкривали (ПК був вимкнений).

Банер у Налаштуваннях запропонує «Вказати папку заново» — це не втрата
даних, робота застосунку від цього не блокується.
